Extensões com interface própria e acesso autorizado a recursos.

Apresente o objetivo: permitir que desenvolvedores ampliem o MLX-Pilot com ferramentas que a pessoa e a IA possam usar. A inspiração do SillyTavern está no manifesto e no gerenciamento de extensões. O que veremos é a implementação específica deste repositório, com WASM, frontend isolado e autorizações do host.

Inspiração: o modelo de extensões do SillyTavern.

Explique o problema de manutenção antes de falar de tecnologia. O núcleo continua responsável por políticas e persistência. Ter um pacote separado permite adicionar funcionalidades sem dar ao plugin acesso irrestrito ao aplicativo. O Studio é uma integração embarcada, enquanto os pacotes de terceiros usam as capacidades públicas.

O plugin não recebe o DOM principal, shell ou acesso arbitrário a arquivos.

Leia o diagrama da esquerda para a direita. A pessoa usa o frontend e o agente invoca ferramentas. O daemon verifica permissões. Ferramentas executam no WASM e o broker controla recursos externos. O frontend também pode chamar as APIs autorizadas do broker. O cofre injeta a credencial no cabeçalho HTTP e não a devolve ao plugin. A origem opaca do iframe e o token de cada abertura protegem a ponte. Navegar o iframe invalida a ponte. O usuário instala o pacote pronto. Não precisa executar um build.

O arquivo real contém manifest e wasm_base64. O frontend é opcional, mas suporta experiências visuais completas. Ferramentas têm nome, descrição, JSON Schema, export WASM e indicador mutating. A instalação valida e compila o módulo antes de persistir. SHA-256 detecta alteração do WASM persistido, mas não equivale a assinatura de autor. O SDK atual é 2.0.0 e o manifesto mantém api_version 1.

WASM: cliente síncrono. Frontend: as mesmas APIs com Promises.

Este é um recorte da implementação, não o manifesto completo. A função precisa fazer parte de uma ferramenta com JSON Schema e declarar network:request, além do serviço open_library. O exemplo completo está em plugins/reading-notes. createHostClient é síncrono dentro do WASM. createFrontendClient é assíncrono no navegador e também oferece invoke para ferramentas do próprio plugin. O SDK usa TypeScript/JavaScript e as etapas init, test, build e pack. Compilar exige as ferramentas de desenvolvimento, mas instalar o pacote não.

Permissões e credenciais

O usuário decide o alcance

Serviços

Destino, métodos e autorização explícita de rede local.

Credenciais

Campo de senha. O plugin recebe apenas o status de configuração.

Documentos

IDs selecionados. Criar novos projetos exige uma autorização separada.

Serviços, documentos e chaves são configurados por workspace.

Serviços começam desabilitados e nenhum documento é autorizado por padrão. Os grants das permissões são da instalação. Serviços, chaves e documentos são separados por workspace. O usuário pode manter, substituir ou remover a chave pelo campo de senha. A API retorna apenas credential_set. O SDK não possui credentials.get ou credentials.set. Alterações no conjunto de serviços e permissões exigem reautorizar recursos. Revogar qualquer grant necessário bloqueia o plugin.

Demonstração 02 / Reading Notes

Pesquisa real, documento editável

02
Reading Notes é um plugin de terceiros completo, com WASM e frontend. A consulta usa HTTPS/GET pelo broker para o serviço Open Library autorizado. O plugin consulta até cinco livros e cria um projeto com briefing, metadados e fontes. Não deduz nem resume o conteúdo dos livros a partir do catálogo. Criar o projeto exige documents:write e allow_create. O ID criado passa a integrar os documentos autorizados do plugin.

O projeto estruturado é a fonte comum dos formatos. O PDF é rasterizado e não tem texto selecionável. PPTX nativo preserva textos, formas, imagens, tabelas, gráficos e notas, mas não traduz CSS arbitrário nem animações. PPTX visual preserva a aparência como uma imagem por slide. Nomes, descrições e schemas tornam as capacidades disponíveis ao modelo local.

O pedido é ilustrativo, não uma transcrição da demonstração. O nome público de ferramentas de terceiros usa plugin_id, dois underscores e tool_name. O catálogo é reconstruído a cada execução. ReadOnly e DryRun bloqueiam mutações. Locked bloqueia ferramentas. Uma ferramenta que grava documentos ou envia métodos HTTP além de GET, HEAD e OPTIONS deve declarar mutating: true. Para compor apresentações no Studio, a IA segue planejamento, composição por slide, revisão editorial e preflight. O modelo de texto recebe metadados e descrições de imagens, não os bytes.

Os totais registram a verificação de 18 de outubro de 2026 informada para esta entrega, não uma garantia de ausência de bugs. O README e o roteiro local registram a evidência e o escopo. WASM: 100 milhões de instruções de combustível, memória de 256 MiB, timeout de 5 s sem broker e 60 s com broker. HTTP: 15 s por requisição, 45 s de prazo total do broker e limite de 1 MiB por corpo. Rede local exige opt-in. O preflight do Studio mede cortes, sobreposições e contraste quando mensurável. CSS arbitrário e imagens sob texto ainda exigem inspeção humana. SHA-256 não é assinatura de confiança.
